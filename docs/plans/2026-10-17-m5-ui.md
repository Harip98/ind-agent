# M5 Thin Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single demo page served by ai-svc where a person picks a tenant, asks a question, and sees the incident report: summary, observations, ranked explanations, recommendation, warnings, Chart.js readings with the alarm marked, clickable citations with section text and stale badges, clarification options as buttons, and timings.

**Architecture:** Static files (`index.html`, `app.js`, `style.css`) inside the `copilot` package under `web/`, served by FastAPI (`GET /` and `/static/*`). The page calls the existing `POST /investigate` with a bearer token. For demos only, `copilot serve --dev` enables `GET /dev/defaults` (tenants, simgen `as_of`) and `POST /dev/token` (mint a 1 h dev token for a tenant); both return 404 unless dev mode is on, and the server binds to 127.0.0.1. Chart.js is loaded from cdnjs at a pinned version.

**Tech Stack:** FastAPI StaticFiles, vanilla JS (no build step), Chart.js 4.4.1 (cdnjs), CSS custom properties with light/dark themes.

**Spec:** [docs/architecture.md](../architecture.md) §4.2; M5 in [docs/plan.md](../plan.md).

## Global Constraints

- No new backend data paths: the UI only uses `/investigate` (+ dev helpers in dev mode).
- Dev token minting must be impossible unless `--dev` (env `COPILOT_DEV_MODE=true`) is set; never enabled in compose.
- All rendering via `textContent`/DOM APIs — never `innerHTML` with response data (citations contain untrusted document text, including an injection fixture).
- Works without the network except for Chart.js; if Chart.js fails to load, the report still renders (charts show a note).
- Responsive down to 360 px; keyboard-usable controls; respects `prefers-color-scheme`.

## Review Focus

1. **Dev endpoints reachable without `--dev`** — 404 → Task 1 `test_dev_endpoints_disabled_by_default`.
2. **Document text containing HTML/script** — rendered as text → Task 2 manual check with the BULLETIN-VEND-14 injection section + code review (`innerHTML` absent: `test_ui_never_uses_innerhtml`).
3. **Clarification flow** — clicking an option re-asks with `asset_id`/`alarm_id` → Task 3 browser check.
4. **Error statuses (401/429/503)** — shown as readable messages, form usable again → Task 2.
5. **Large responses (~200 KB, 6 series × 480 points)** — page stays responsive → Task 3 browser check.

```python
def test_ui_is_served(sim):
    c = _client(sim)
    r = c.get("/")
    assert r.status_code == 200 and "text/html" in r.headers["content-type"] and "ind-agent" in r.text
    assert c.get("/static/app.js").status_code == 200


def test_dev_endpoints_disabled_by_default(sim):
    c = _client(sim)
    assert c.get("/dev/defaults").status_code == 404
    assert c.post("/dev/token", json={"tenant": "acme"}).status_code == 404


def test_dev_endpoints_in_dev_mode(sim, monkeypatch):
    monkeypatch.setenv("COPILOT_DEV_MODE", "true")
    from copilot.config import get_settings
    get_settings.cache_clear()
    try:
        c = _client(sim)
        d = c.get("/dev/defaults").json()
        assert d["tenants"] == ["acme", "globex"] and "as_of" in d
        tok = c.post("/dev/token", json={"tenant": "acme"}).json()["token"]
        assert c.post("/investigate", json=BODY, headers={"Authorization": f"Bearer {tok}"}).status_code == 200
        assert c.post("/dev/token", json={"tenant": "evil"}).status_code == 400
    finally:
        monkeypatch.delenv("COPILOT_DEV_MODE")
        get_settings.cache_clear()


def test_ui_never_uses_innerhtml():
    from copilot.api import WEB_DIR
    assert "innerHTML" not in (WEB_DIR / "app.js").read_text(encoding="utf-8")
```

### Task 2: The page

**Files:** `src/copilot/web/index.html`, `app.js`, `style.css`.

Layout (single column on mobile, two columns ≥ 1000 px):
- Header: product name, "synthetic data" badge, tenant select (dev mode) or token field, mode select (template / llm), as-of input (prefilled from `/dev/defaults`).
- Question form with three example-question chips per tenant.
- Result: status badge; clarification card with option buttons; summary; warnings (`insufficient_evidence`); explanations (label, confidence chip, score, text, ref chips — clicking an O-ref scrolls to and highlights the observation, a D-ref opens the citation); recommendation card with ref chips; observations list; charts grid (one small chart per tag, alarmed tag first and larger, avg line + min/max band, vertical alarm line drawn by a tiny inline Chart.js plugin); citations list (`doc vX §n heading`, stale badge, expandable content); footer with trace id, timings, LLM model/tokens/attempts.
- Errors: 401 → "token invalid or expired"; 429 → "rate limited, retry in a second"; 503 `llm_unavailable` → offer "retry in template mode" button; others → message + trace id.
- Rendering only through `document.createElement` / `textContent`.

- [ ] Use the frontend-design skill for visual direction (calm, technical, industrial; high-contrast status colours; no gratuitous decoration).
