# M6 Agent-Loop Experiment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure whether letting the local LLM drive the investigation with tools (approach B) beats the code-driven pipeline (approach A) on this hardware — same questions, same verifier, same scoring.

**Architecture:** `mode="agent"`: `copilot.agent.run_agent` gives `qwen2.5:7b-instruct` (Ollama native tool calling) six read-only tools and at most 6 steps: `list_assets`, `find_alarms(asset_id, start, end, alarm_type?)`, `analyze_alarm(alarm_id)` (returns the deterministic observations + candidate causes), `search_procedures(query)`, `submit_report(alarm_id, explanations, recommendation)`, `ask_clarification(message)`. Tools take the tenant from the verified principal (never from arguments) and call data-svc with the user's token. `submit_report` runs the same verifier as the pipeline (one corrective round); output has the pipeline's response shape so `copilot eval --mode agent` scores it unchanged.

**Tech Stack:** Ollama `/api/chat` with `tools`; existing pipeline modules.

**Spec:** [docs/architecture.md](../architecture.md) §2 (why approach A) and M6 in [docs/plan.md](../plan.md).

## Global Constraints

- Tools are read-only; arguments validated (ids `^[A-Za-z0-9_:-]{1,140}$`, windows ≤ 30 days, alarm types from the known set); tool results truncated to ≤ 4 kB.
- Tenant only from the principal; a foreign asset/alarm id behaves exactly like an unknown one.
- ≤ 6 LLM turns; no submission → `status: agent_failed` (scored as wrong).
- Same verifier, deterministic summary, canonical cause order and confidence as the pipeline.
- Measured on the test split (50) in `agent` mode; compared with `llm` mode on the same split.

## Review Focus

1. Agent passes another tenant's asset id to a tool → NotFound, same as unknown → `test_agent_tools_use_principal_tenant`.
2. Agent loops without submitting → stops at 6 turns with `agent_failed` → `test_agent_step_limit`.
3. Agent submits refs to evidence it never retrieved → verifier rejects → `test_agent_submission_verified`.
4. Malformed tool arguments (bad dates, huge windows) → tool error message back to the agent, not a crash → `test_agent_bad_arguments`.
5. Injection in a retrieved procedure tells the agent to call a different tool → no write tools exist; unsafe advice still blocked by the verifier.
